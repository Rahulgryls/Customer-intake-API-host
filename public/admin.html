Customer Intake API — Admin Portal

Create mock APIs for stubbing, then browse and edit the JSON files behind every API
What this creates: a generic stub endpoint that stores and returns whatever JSON you give it — useful for POC/simulation across teams. It does not generate business rules (query-param filtering, custom validation) — those still need to be coded by hand, same as the three built-in APIs (Customer Details, Risk Profile, Transaction History). It can simulate error responses though: add a top-level "__status": 422 field to any stored record (in the Manage Data editor) to make that record's GET reply with that HTTP status instead of 200 — handy for testing a consuming app's error handling. When GitHub persistence is configured on this server, everything here is automatically mirrored to GitHub in the background and restored on every startup — otherwise it's local-disk only and resets on redeploy.
